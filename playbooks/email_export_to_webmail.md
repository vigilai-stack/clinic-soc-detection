# Patient file sent to personal webmail

## What happened

A clinic mailbox sent a large csv, spreadsheet, or zip to a personal webmail domain such as gmail.com. Ordinary reminders are small PDFs and do not match.

## Why it matters here

Personal webmail is not a clinic system and not a business associate. A file named like an export is patient information leaving.

## What to do first

1. Call Sangeeta Sinha (555-0108) and Sam Patel (555-0174). Tell Avery Brooks (555-0142) so the employee is not tipped off by a hallway conversation first.
2. Block further external sending from that mailbox.
3. If the sender is still in the clinic, Avery asks them to step away from the keyboard. Disable the EHR account if an export alert names them.
4. Do not forward the message, and do not download the attachment onto another clinic PC "just to look." IT can review a copy on a machine that is not used for charts.
5. Ask the mail provider, through the gateway admin, whether the message can be recalled. Often it cannot. Write down the answer.

## What to isolate

The mailbox's external send, and the EHR account if the file came from an export. Do not delete the mailbox. You need the sent-item record.

## Evidence to keep

Sender, recipient, time, file name, size, and whether the gateway shows the message as delivered.

## Breach-notification considerations

A delivered file of patient rows to personal webmail is the fact pattern counsel treats as a likely breach, because the clinic no longer controls the copy. Start the assessment the same day and call the cyber insurer. Do not email the affected patients from the same mailbox. This checklist is not legal advice.

## False alarms

A staff member sending a large personal spreadsheet from the clinic mailbox will look the same. The file name and a conversation tell you which it is. Either way, staff should not use clinic mail for that.
